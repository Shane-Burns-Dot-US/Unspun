# Unspun — Data Model

The concrete data model for the platform. It exists in **two representations of one
truth** (Building Ethos, Tenet 3):

1. **`catalog/` — the atomic catalog (YAML).** The *authoritative source*. Format‑neutral
   "particles" (entities, fields, value types, enums) that can be re‑composed into many
   "molecules." Human‑auditable and machine‑readable.
2. **`sql/` — the reference molecule (Postgres DDL).** *One* composition of the atoms into a
   relational schema. Generated by the mechanical mapping in §4. Other molecules (a graph
   view, a document store, an analytics star) are equally valid and live as alternative
   compositions of the same atoms (the "side‑set index", Ethos Tenet 6).

**Baseline:** the MECE v2 recut — 12 subject contexts × 8 archetypes, the Party identity
pattern, the dynamic layer (events / processes / checks), and the Chesky granular
additions. See [`../spec/`](../spec/) for the why.

---

## 1. The 12 contexts (Axis 1 — ownership)

`1` Parties & Consent · `2` Taste & Creative · `3` Supply · `4` Commercial & Finance ·
`5` Event Design · `6` Production & Logistics · `7` Risk & Resilience ·
`8` Communication & Relationship · `9` Acquisition & Distribution · `10` Operations & Team ·
`11` Safety & Compliance · `12` Platform & Governance.
Plus two cross‑cutting **layers**: `dyn` Dynamic (events/process/checks) and
`ai` AI Enablement.

## 2. The 8 archetypes (Axis 2 — kind)

`root` Aggregate Root · `member` Aggregate Member · `party` Party/Identity ·
`master` Master/Catalog · `policy` Policy/Standard · `signal` Signal/Record (append‑only) ·
`projection` Derived/Projection (no independent truth) · `value` Value Object (embedded).

Every entity declares exactly one `context` and one `archetype`.

## 3. Conventions (apply to every entity)

- **Primary key:** `id text` = `<prefix>_<ulid>` — deterministic, sortable, self‑describing
  (Ethos Tenet 1). Prefix registry: [`../spec/glossary.md`](../spec/glossary.md) + new
  prefixes in the catalog files.
- **Audit columns** (every `root`/`member`/`party`/`master`/`policy` table):
  `created_at timestamptz not null default now()`, `updated_at timestamptz not null`,
  `created_by text`, `updated_by text` (actor ids). Marked `+audit` in YAML.
- **Soft delete:** `deleted_at timestamptz null` (`+soft`). Append‑only `signal` tables are
  never soft‑deleted; they are superseded.
- **Provenance & consent** (any sourced/sensitive fact): `provenance provenance`,
  `consent_id text`, `expires_at timestamptz`, `sensitivity sensitivity_class`
  (`+sourced`). Enforced by the governance rules in the spec.
- **Versioning** (`master`/`policy`): `version int`, `effective_from`, `effective_to`,
  `supersedes_id` (`+versioned`). Versions are immutable.
- **State:** stateful entities carry `state <enum>` and are indexed on it; legal transitions
  live in the dynamic layer (`state_transition`), not as free updates.
- **Foreign keys:** `<entity>_id`. Cross‑context links are plain references; within an
  aggregate they cascade with the root.
- **Money/time/geo** are kernel value types (§4, `00-kernel.yaml`), embedded as composite
  columns so the atom survives into the molecule.

## 4. Atom → molecule mapping (how YAML becomes SQL)

| Catalog atom | Postgres molecule |
|---|---|
| `enum` | `CREATE TYPE … AS ENUM` |
| `value` type | composite `CREATE TYPE` (or embedded columns) |
| entity | `CREATE TABLE` named `snake_case(plural)` |
| `field: {type}` | column; `req:true` → `NOT NULL` |
| `+audit/+soft/+sourced/+versioned` mixin | the standard column sets above |
| `relation kind:fk/composition` | `FOREIGN KEY` (composition → `ON DELETE CASCADE`) |
| `relation kind:ref` | `FOREIGN KEY … ON DELETE RESTRICT` (loose link) |
| `natural_key` | `UNIQUE` constraint |
| `states` | `state` column of the entity's status enum |

Type shorthands used in YAML: `txt str int num bool ts date jsonb uuid` and the kernel
value types (`money geopoint datewindow provenance score`). `[T]` = array/collection
(`text[]`/`jsonb` in SQL, or a child table). `T?` = nullable.

**Molecule‑specific renames** (catalog name → SQL identifier, to dodge Postgres
keywords/builtins): the `money` value type → composite `money_amount` (`money` is a
built‑in pg type); any field literally named `window` → column `time_window` (`WINDOW` is
a reserved word). The atom keeps its conceptual name; only this molecule remaps it.

## 5. How to extend (Ethos: small steps, atoms first)

Add the entity to the right `catalog/*.yaml` first (one context, one archetype, a prefix),
then regenerate/extend `sql/`. Never add a SQL table without its catalog atom. Prefer many
small fields/child‑tables over wide JSON blobs, except where a blob is a genuine
opaque atom (e.g. `aesthetic_vector`).
